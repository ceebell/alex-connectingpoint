# Note และข้อมูลติดต่อของลูกค้า

แอดมินเปิดแท็บ **Note** ของลูกค้าเพื่อเพิ่มข้อความและรูปภาพ แก้ไข หรือกด **ลบ** บนโน้ตที่เคยบันทึก การลบต้องยืนยันก่อน และข้อความใหม่ที่ยังไม่ได้บันทึกจะยังอยู่ ตัวอักษรในเนื้อหาโน้ต ช่องเขียน และประวัติใช้ขนาดเดียวกับข้อความแชททั้งบนคอมพิวเตอร์และมือถือ

คลิกรูปแนบหรือรูปที่กำลังเตรียมใน Note เพื่อดูภาพขยายใน modal บนหน้าเดิม ปิดด้วยปุ่ม **ปิดรูปภาพ**, Esc หรือคลิกพื้นหลังได้ ข้อความและรูปที่ยังไม่ได้บันทึกจะยังอยู่ และการเปิดดูรูปไม่บันทึกหรือส่งรูปให้ลูกค้า

## การลบ

- `DELETE /api/line/users/{user_id}/notes/{note_id}` รับ `{ "expected_version": 1 }` ผ่าน session และ `X-Admin-Request` เช่นเดียวกับการแก้ไข
- ตรวจร้าน ช่อง LINE ลูกค้า และเวอร์ชันก่อนลบ หากแอดมินอีกคนแก้โน้ตไปแล้ว จะโหลดเวอร์ชันล่าสุดให้ตรวจและกดลบใหม่
- บันทึก `deleted_at`, `deleted_by`, `deleted_by_id` และประวัติ `DELETE` แบบ atomic โดยเก็บข้อมูลเดิมไว้สำหรับ audit การส่งคำขอลบเดิมซ้ำไม่เพิ่มเวอร์ชันหรือประวัติซ้ำ
- โน้ตที่ลบไม่แสดงในรายการ เปิดรายละเอียดหรือรูปไม่ได้ และไม่ใช้ค้นข้อมูลติดต่อหรือจับคู่ชื่อผู้รับพัสดุ การส่งคำขอสร้างโน้ตเดิมซ้ำไม่ทำให้โน้ตที่ลบกลับมา

## ลำดับชื่อและเบอร์โทร

ทั้งปุ่ม **ค้นข้อมูลลูกค้า** และ **เตรียมออเดอร์ด้วย AI** ใช้ลำดับต่อช่องข้อมูล:

1. ข้อความขาเข้าของลูกค้าในแชทปัจจุบัน ใช้การแก้ข้อมูลที่ระบุชัดเจนล่าสุด
2. ข้อความใน Note ที่ยังไม่ลบของลูกค้ารายนั้น ใช้เติมเฉพาะช่องชื่อหรือเบอร์โทรที่แชทยังไม่มี เรียงการแก้ไขล่าสุดก่อน

ไม่อ่านชื่อ Display ของ LINE/OA หรือชื่อที่แอดมินตั้งเองมาเป็นข้อมูลติดต่อ และไม่ส่งชื่อเหล่านี้ให้ AI ในขั้นตอนค้นข้อมูล หากแชทมีข้อมูลขัดแย้ง จะเว้นช่องนั้นและแจ้งให้ตรวจ ไม่เลือก Note แทน ที่อยู่ยังต้องอ้างอิงแชทลูกค้า รูปใน Note ไม่ถูกส่งให้ AI อ่านข้อมูลติดต่อ ชื่อฟิลด์ API `display_name` ในผลค้นหาหมายถึงชื่อผู้รับที่อ่านจากแชทหรือ Note เท่านั้น

ระบบตรวจข้อความอ้างอิงกับแหล่งข้อมูลจริงและตรวจลำดับอีกครั้งบน server ข้อมูลใน Note และแชทถือเป็นข้อมูลที่ไม่น่าเชื่อถือ ไม่เปิดใช้เครื่องมือหรือรันคำสั่งจากข้อความเหล่านี้ และไม่อ่านข้อมูลลูกค้าหรือร้านอื่น หาก Note หรือแชทถูกเพิ่ม แก้ หรือลบระหว่าง AI ทำงาน จะปฏิเสธผลเก่าให้เตรียมใหม่ การเปลี่ยนชื่อ Display ไม่เปลี่ยนผลค้นข้อมูลติดต่อ

การอ่านข้อมูลติดต่อรองรับข้อความโน้ตสูงสุด 200 รายการ รวม 50,000 ตัวอักษรต่อครั้ง หากเกินจะแจ้งข้อผิดพลาดแทนการอ่านเพียงบางส่วน การกรอกและบันทึกร่างด้วยมือยังใช้ข้อมูลที่แอดมินระบุ
