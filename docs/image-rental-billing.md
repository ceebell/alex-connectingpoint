# สรุปจากรูป → เลือกชุด → เช็คคิว → สร้างบิลใน Alex

## การใช้งาน

1. เลือก inquiry และเปิด **สรุปแอดมิน** กด **แนบรูป** ได้รวมสูงสุด 5 รูปต่อร่าง รวมรูปที่เลือกจากแชทด้วย เขียนคำบรรยายเพิ่มได้แต่ไม่บังคับ วันที่ที่มีวันและเดือนชัดเจนแต่ไม่ระบุปีจะใช้ปีปัจจุบันตามเวลาไทย ณ เวลาสร้างคำขอ AI (วันรับชุดและวันคืนชุดของแต่ละชุด — Alex ใช้เพียงสองวันนี้ ไม่มีช่องวันใช้งานหรือวันส่งชุด) หากระบุปีไว้จะใช้ปีนั้นและแปลง พ.ศ. เป็น ค.ศ. รูปแนบส่วนนี้เป็นข้อมูลภายใน ไม่ถูกส่งให้ลูกค้าทาง LINE
2. กด **เตรียมออเดอร์ด้วย AI** ระบบอ่านเฉพาะรูปที่เลือกและสรุปแอดมิน ไม่ส่งแชทหรือร่างเก่าให้ AI กวาดออเดอร์/สินค้า จากนั้น backend ล็อกอิน Alex แล้วค้น `POST /api/v2/GetProductItems` ด้วยชื่อหรือรหัส สี และไซซ์ที่สกัดได้ เมื่อพบตรงกันรายการเดียวจะเติมรหัส ชื่อ สี ไซซ์ ค่าเช่า/มัดจำที่ยังว่างจาก API ลงร่างพร้อมหลักฐาน โดยคงยอดที่แอดมินระบุไว้แล้ว
3. เบอร์โทรถูกบันทึกโดยตัดช่องว่างและขีดกลางออกเสมอ (เช่น `081-234 5678` → `0812345678`) ทั้งในร่าง โปรไฟล์ลูกค้า และบิล Alex กด **ค้นข้อมูลลูกค้าจากแชท** ในแท็บ **ลูกค้า**, **ร่างล่าสุด** หรือ **คิว/บิล** ระบบเติมชื่อ เบอร์โทร ที่อยู่จากข้อความลูกค้าในเรื่องนี้ พร้อมข้อความอ้างอิง ช่องที่ไม่พบข้อมูลคงค่าเดิม และยังต้องกดบันทึกหรือยืนยันบิล ข้อความร้านและรูปแนบภายในไม่ถูกใช้เป็นข้อมูลติดต่อของลูกค้า
4. เปิด **เลือกชุด** จะเห็นผลค้นหาอัตโนมัติจากข้อ 2 ทันที ตรวจและยืนยัน Product ID สี ไซซ์ทุกชิ้น ชุดที่ยืนยันแล้วแสดงเป็นการ์ดพร้อมรูป ชื่อ รหัส สี ไซซ์ ราคา ค่าประกัน ปรับจำนวนด้วยปุ่ม −/+ (1–999; ถ้าไม่ระบุจำนวนจะเป็น 1) และกด **เอาออก** เพื่อยกเลิกชุดนั้นแล้วค้นใหม่ได้ จำนวนบนการ์ดคือจำนวนที่ใช้เช็คคิวและออกบิล หากพบหลายตัวเลือก สี/ไซซ์ต่างจากสรุป หรือไม่พบสินค้า ระบบถามให้เลือก/ค้นเพิ่มแทนการเดา เลือกได้เฉพาะสาขาที่ได้รับสิทธิ์ หากบัญชีมีหลายสาขาและสรุปไม่ได้ระบุ ให้เลือกสาขาก่อนค้น
5. เปิด **คิว/บิล** ระบบแยกกลุ่มตามสาขา ช่วงเช่า วิธีรับ และขนส่ง เลือกทำบิลทีละกลุ่ม กด **เช็คคิวจาก Alex** ผลว่างเป็นผล ณ เวลาตรวจ ยังไม่กันคิว
6. ตรวจลูกค้า กรอก **ส่วนลดค่าเช่า** และ **ส่วนลดค่าประกัน** (เริ่มที่ 0 ไม่เกินยอดแค็ตตาล็อก) ค่าส่ง วิธีชำระ และหมายเหตุ กด **ตรวจคิวและเตรียมบิลให้ตรวจ** ระบบตรวจ catalog/ราคา/คิวซ้ำและสร้างใบตรวจภายในอายุ 5 นาที ยังไม่มีการสร้างออเดอร์ใน Alex
7. อ่านรายละเอียดและติ๊กยืนยัน แล้วกด **ส่งสร้างบิล / ออเดอร์ใน Alex** ระบบตรวจต้นฉบับและคิวอีกครั้งก่อน POST จริง ผลและประวัติอยู่ในแท็บนี้ การ **อนุมัติร่างภายใน** เป็นการเก็บร่างในระบบเดิม แยกจากการส่งบิลเข้า Alex

## ภาพตัวอย่างและข้อมูลที่ต้องตรวจ

- **nina — dark brown — M:** 3 วันเป็นระยะเช่า ค่าเช่า 550 บาท ค่าส่ง Flash 40 บาท เข็มกลัดดอกไม้อยู่ในหมายเหตุ “รับชุด 5,6” ยังไม่ใช่วันรับที่แน่นอน วันส่ง 4/11 ไม่ใช่วันรับชุด จึงไม่ถูกบันทึก
- **Haatiya — Blush Pink:** ข้อความจองเลือก M แม้โปสเตอร์มี S,M จึงไม่เพิ่มจำนวนเป็นสองชุด รับ 12/11 คืน 15/11 ใช้ปีปัจจุบันเมื่อไม่ได้ระบุปี (วันใช้งาน 14/11 ไม่ถูกบันทึก) ตารางราคา 1/3/5 วันยังไม่ใช่ยอดที่ตกลง ให้แอดมินเลือกยอดจริง
- หากสองชุดใช้คนละช่วงวัน จะได้สองกลุ่มบิล ข้อมูลร่วมใช้เฉพาะช่องที่รายการนั้นยังไม่ได้ระบุ รูปซ้ำไม่เพิ่มจำนวนชุดอัตโนมัติ
- ไม่ใช้ชื่อชุดหรือผล AI เป็น Product ID ต้องค้นและยืนยันสินค้าจริงจาก Alex ก่อน

## ข้อตกลง API และการตั้งค่า

ใช้บัญชีและขอบเขตจาก [คู่มือ Step 3](step-3-products.md) และ config ฝั่ง server เท่านั้น ไม่มี token หรือรหัสผ่านใน frontend

- `POST /api/orderdetail/checkq`: ส่ง array ทีละรายการ `{productItemId,pickupDate,returnDate,branchId,qty}` อ่าน `result=1` ว่าง, `0` ไม่ว่าง; HTTP/schema ผิดหรือค่าอื่นเป็น “ยังตรวจไม่ได้” ไม่เปิดให้ส่งบิล รองรับวันที่ตอบกลับ `YYYY-MM-DDT00:00:00` ที่ตรวจพบใน API จริง
- `POST /api/v2/AddRentalOrder`: สร้างตาม `prompts/orderheader_create.json` และใช้รายการที่ยืนยันแล้ว `rentalDiscount`/`bailDiscount` มาจากช่องส่วนลดค่าเช่า/ส่วนลดค่าประกันที่แอดมินกรอก (สตางค์) ไม่รองรับส่วนลดติดลบหรือเกินยอดแค็ตตาล็อก ไม่มีการใส่วันเกิดสมมติหรือเปิดโปรโมชั่นเอง
- template นี้ไม่มีช่องค่าจัดส่งแยก เมื่อมีค่าส่ง ระบบต้องให้แอดมินรับทราบก่อนบันทึกเป็นหมายเหตุ **ยอดค่าเช่าใน Alex ไม่รวมค่าส่ง** หากต้องการรวมเป็นยอดเรียกเก็บแยก ต้องเพิ่ม contract ค่าส่งที่ Alex รองรับก่อน
- ตัวอย่างสองไฟล์ที่ได้รับเป็น request จึงยังไม่ยืนยันชื่อฟิลด์เลขบิลใน response ตั้ง `ALEX_ORDER_ID_POINTER` ใน `.env` บน server **หลังตรวจ response สร้างสำเร็จจริงแล้วเท่านั้น** เช่น `/orderId` หรือ `/data/orderId` ตามข้อมูลจริง; `$` ใช้เฉพาะเมื่อ response สำเร็จเป็นเลข/ข้อความ ID โดยตรง ตัวอย่างเหล่านี้ไม่ใช่ schema ที่ตรวจยืนยันแล้ว
- ค่าเริ่มต้น `ALEX_ORDER_ID_POINTER` ว่าง: ส่งคำขอได้ แต่จะขึ้น “ต้องตรวจผลใน Alex” จนแอดมินตรวจบิลและบันทึกเลขออเดอร์ ระบบไม่ใช้เพียง HTTP 2xx ยืนยันว่ามีบิล

## ผลตอบกลับไม่ชัดเจนและการส่งซ้ำ

คำขอส่งบิลมี ID คงที่ บันทึกก่อน POST และส่งเพียงครั้งเดียว การกดซ้ำด้วย ID เดิมอ่านผลเดิม กลุ่มรายการที่ทับกับบิลเดิมใน inquiry ถูกกันไว้ ระบบกู้สถานะหลังรีสตาร์ตและอ่านประวัติได้แม้แชทหรือร่างเปลี่ยนไป

หาก timeout, HTTP error, หรืออ่านเลขบิลไม่ได้ จะเก็บ `SUBMIT_UNKNOWN` และล็อกการส่งบิลใหม่ของเรื่องนี้ ให้ตรวจใน Alex แล้วกด **บันทึกผลที่ตรวจจาก Alex**: ถ้าพบ ให้กรอกเลขออเดอร์; ถ้าไม่พบ ต้องรออย่างน้อย 2 นาทีจากการส่งครั้งล่าสุดและตรวจ Alex ก่อนยืนยันว่าไม่ได้สร้าง การเปิดให้ส่งใหม่อาศัยการตรวจของแอดมิน เนื่องจากยังไม่มี API ตรวจสถานะคำขอหรือ server idempotency ของ Alex ที่ยืนยันแล้ว

ระบบไม่รับประกันการกันคิวระหว่างผลตรวจและการสร้างบิล หากมีผู้ใช้อื่นจองพร้อมกัน ผลสุดท้ายขึ้นกับ Alex

## ข้อมูลและการทดสอบ

รูปภายในเก็บ GridFS ตามอายุ `LINE_MEDIA_RETENTION_DAYS` และต้องล็อกอินเพื่อเปิด ใช้รวมกับรูปจากแชทไม่เกิน 8 MB ต่อการส่ง AI; browser ลดภาพเหลือด้านยาว 2,000 px และไม่เกินประมาณ 1.4 MB ต่อรูป ข้อมูลลูกค้าต้องมีหลักฐานข้อความลูกค้าตรงตัวและตรวจ context ใหม่ก่อนเติม

collections ใหม่: `inquiry_attachments`, `availability_checks`, `bill_reviews`, `alex_submissions`; มี index แยก shop/channel/inquiry และ unique reservation ที่ active MCP ยังคงมีเพียงเครื่องมือค้นหาแบบอ่านข้อมูล ไม่เพิ่มเครื่องมือสร้างบิล

ทดสอบ API ด้วย MongoDB disposable: `cargo test -- --include-ignored` และ `TEST_MONGODB_URI` ที่ชี้ฐานทดสอบ การทดสอบสร้างบิลใช้ Alex จำลองเท่านั้น ส่วน production ทดสอบอ่าน login/catalog/checkq โดยไม่สร้างบิลจริง

## Build และ deploy

Windows build บน local เท่านั้น ใช้ `build-backend.bat` และ `build-frontend.bat` แล้วผู้ใช้รัน `rungit.bat "เพิ่มสรุปจากรูปและสร้างบิล Alex"` เอง เมื่อมี release พร้อมแล้ว ไม่ต้อง build โปรแกรมซ้ำบน Ubuntu

Ubuntu:

```sh
ssh Hermes
cd ~/alex-connectingpoint
bash ./loadgit.sh main
sudo bash ./docker-build.sh --full-stack
sudo bash ./docker-deploy.sh --full-stack
```

หากแก้เฉพาะ `.env` บน server ให้รันเฉพาะ deploy คำสั่งสุดท้าย ตรวจ credentials/branch และ extraction profile Hermes ตามคู่มือ Step 2/3 ก่อนใช้งานจริง
