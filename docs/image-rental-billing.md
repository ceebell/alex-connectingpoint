# สรุปจากรูป → ร่างออเดอร์และตะกร้า → เช็คคิว → สร้างบิลใน Alex

## การใช้งาน

1. เลือก inquiry และเปิด **สรุปแอดมิน** กด **แนบรูป** ได้รวมสูงสุด 5 รูปต่อร่าง (รูปที่แนบลบได้ด้วยปุ่ม 🗑 มุมรูป ระบบลบไฟล์และเอาออกจากรูปที่เลือกในสรุป ร่างเดิมต้องเตรียมใหม่เหมือนตอนแนบรูปเพิ่ม) รวมรูปที่เลือกจากแชทด้วย เขียนคำบรรยายเพิ่มได้แต่ไม่บังคับ วันที่ที่มีวันและเดือนชัดเจนแต่ไม่ระบุปีจะใช้ปีปัจจุบันตามเวลาไทย ณ เวลาสร้างคำขอ AI (วันรับชุดและวันคืนชุดของออเดอร์ — Alex ใช้เพียงสองวันนี้ ไม่มีช่องวันใช้งานหรือวันส่งชุด หากรูปมีวันต่างกัน AI จะถามว่าจะแยกออเดอร์หรือไม่) หากระบุปีไว้จะใช้ปีนั้นและแปลง พ.ศ. เป็น ค.ศ. รูปแนบส่วนนี้เป็นข้อมูลภายใน ไม่ถูกส่งให้ลูกค้าทาง LINE
1.1 คำบรรยายวางเป็น **สรุปบิล** ที่แอดมินส่งลูกค้าได้ (ตัวอย่างใน `prompts/ai-order-summary-ex.md`) ถ้าส่งบิลในแชทไปแล้ว กด **ใช้สรุปบิลล่าสุดจากแชท** เพื่อคัดลอกข้อความล่าสุดของแอดมินที่มีทั้ง "ค่าเช่า" และ "ค่าประกัน" มาใส่ช่องนี้ (ถามก่อนแทนข้อความเดิม) AI ยังอ่านเฉพาะสรุปนี้ ไม่อ่านแชทเอง กติกาที่ AI ใช้อ่านบิล:
   - บรรทัด `ชื่อ <ประเภท> / <ชื่อชุด> - <สี> / size <ไซซ์> / <N> วัน` = 1 รายการ (หลายบรรทัด = หลายรายการ) คำว่า "ชื่อ" ตรงนี้คือ **ประเภท (category) ของ Alex ไม่ใช่ชื่อลูกค้า** ส่วนหน้า " - " เป็นคำค้นชื่อชุด ส่วนหลังเป็นสีตามที่เขียน "N วัน" เป็นระยะเช่า ไม่ใช่จำนวนชิ้นและไม่ใช้คำนวณวันที่
   - `ค่าเช่า`/`ค่าประกัน` = ราคาที่แจ้งลูกค้า (ยอดรวมทั้งออเดอร์) · `ค่าส่ง` หรือยอดในบรรทัด `จัดส่งชุด` (เช่น `flash 40-.`) = ค่าจัดส่ง, `ฟรี` = 0 · `รวมยอดโอนทั้งหมด` ไม่ถูกบันทึก
   - `ลูกค้ารับชุด` = วันรับ, `ส่งคืนชุด` = วันคืน (เวลา "ขนส่งก่อน 16:00 น." ลงหมายเหตุ) ปีสองหลักหลังชื่อเดือนไทย เช่น `พ.ย 69` คือ พ.ศ. 2569 = ค.ศ. 2026 · `ใช้งานชุด` ลงหมายเหตุตามที่เขียน · วันในบรรทัด `จัดส่งชุด` เป็นวันร้านส่งของ ไม่ใช่วันรับ
   - ข้อความ emoji ของ LINE เช่น `(blue dot dress)` เงื่อนไขร้าน (ชำระภายใน…, ค่าเปลี่ยนชุด, ปรับส่งคืนช้า, ขนส่งที่รับคืน J&T/EMS/DHL) และเลขบัญชี/ชื่อบัญชีของร้าน ไม่ถูกใช้เป็นข้อมูลออเดอร์หรือลูกค้า
2. กด **เตรียมออเดอร์ด้วย AI** ระบบอ่านเฉพาะรูปที่เลือกและสรุปแอดมิน ไม่ส่งแชทหรือร่างเก่าให้ AI กวาดออเดอร์/สินค้า จากนั้น backend ล็อกอิน Alex แล้วค้น `POST /api/v2/GetProductItems` ด้วยชื่อหรือรหัส สี และไซซ์ที่สกัดได้ เมื่อพบตรงกันรายการเดียวจะเติมรหัส ชื่อ สี ไซซ์ลงรายการที่ลูกค้าขอพร้อมหลักฐาน ราคาแค็ตตาล็อกอยู่ในตะกร้า ไม่คัดลอกลงร่าง ถ้ามีประเภทแต่ค้นชื่อชุดในประเภทนั้นไม่พบ ระบบแสดงสินค้าทั้งประเภท (ตามสี/ไซซ์ถ้ามี) ให้เลือกแทน และไม่เลือกให้เอง
3. เปิด **ร่างล่าสุด** ซึ่งเป็นหน้าออเดอร์เดียว (ไม่มีแท็บเลือกชุดและแท็บลูกค้าแล้ว): ส่วน **ลูกค้า** กด **ค้นข้อมูลลูกค้าจากแชท** เพื่อเติมชื่อ เบอร์ ที่อยู่จากข้อความลูกค้าพร้อมข้อความอ้างอิง ช่องที่ไม่พบคงค่าเดิม เบอร์โทรถูกตัดช่องว่างและขีดกลางเสมอ (เช่น `081-234 5678` → `0812345678`) ทั้งในร่างและบิล Alex
4. ส่วน **ค้นหาชุดจาก Alex** มีตัวกรองชื่อ/รหัส/ลิงก์/รูป สี ไซซ์ หมวดหมู่ ลาย ผลค้นหาแสดงรูปจาก Alex ชื่อ รหัส ราคา ค่าประกัน กด **เพิ่มลงตะกร้า** ชิปด้านบนคือสิ่งที่ลูกค้าขอจากรูป/สรุป กดเพื่อดูผลค้นอัตโนมัติจากข้อ 2 หรือเติมคำค้นให้ ระบบไม่เลือกสินค้าเอง
5. ส่วน **ตะกร้าสินค้า** แสดงการ์ดแบบตะกร้า Alex ปรับจำนวนด้วย −/+ (1–999) หรือ **เอาออก** ตะกร้าผูกกับ inquiry และบันทึกทันที การบันทึกร่างเวอร์ชันใหม่ไม่ล้างตะกร้า สินค้าทุกชิ้นต้องอยู่สาขาเดียวกัน
6. ส่วน **วันรับ–คืนชุด**, **ส่วนลดและค่าจัดส่ง** และ **หมายเหตุ** ใช้กับทั้งออเดอร์ (1 inquiry = 1 ออเดอร์ ไม่ใช่ต่อสินค้า) วันที่ทุกชุดที่ AI อ่านได้จากรูป/สรุปแสดงเป็นปุ่ม **วันที่อ่านได้จากรูป/สรุป** กดเพื่อใส่วันรับ/คืน (รูปที่วันต่างกันหรือรับ 5,6 จะได้หลายตัวเลือก ระบบไม่เลือกเอง) **วิธีมารับ** เลือกจากตัวเลือกเดียวกับ Alex (มารับเอง, Line Man, Grab, Kerry, Flash, ขนส่งอื่น) เริ่มต้นเป็น Flash ไม่มีช่องขนส่งและช่องส่งคืนก่อนเวลาแยก (เวลาส่งคืนอยู่ในหมายเหตุ ขนส่งที่ไม่อยู่ในรายการเป็น ขนส่งอื่น และเก็บชื่อไว้ในหมายเหตุ) หลังกดเช็คคิว การ์ดในตะกร้าแสดงป้าย **ติดคิว** สีแดงหรือ **ว่าง** สีเขียว ส่วนลดค่าเช่า/ส่วนลดค่าประกันห้ามเกินยอดแค็ตตาล็อกของตะกร้า ถ้าเว้นว่าง ระบบคิดส่วนลดให้จากราคาที่แจ้งลูกค้าเทียบกับราคาใน Alex ของตะกร้า (เช่น แจ้งค่าเช่า 500 แต่ Alex 700 → ส่วนลดค่าเช่า 200; ค่าประกันคิดแบบเดียวกัน) ช่องแสดงค่า "อัตโนมัติ" ไว้ กรอกตัวเลขเพื่อแทน หรือกรอก 0 ถ้าไม่ให้ส่วนลด ถ้าราคาที่แจ้งสูงกว่า Alex จะขึ้นคำเตือนและบิลใช้ราคา Alex (Alex ไม่มีช่องบวกเพิ่ม) กด **เช็คคิวจาก Alex** ได้ทันทีด้วยวันที่บนหน้าจอ (อ่านอย่างเดียว ไม่กันคิว) แล้วกด **บันทึกร่างเป็นเวอร์ชันใหม่**
7. หลังบันทึกร่าง กดปุ่ม **สรุปออเดอร์และส่งเข้า Alex** ท้ายหน้าร่างล่าสุด (หรือเปิดแท็บ **คิว/บิล**) จะได้ใบสรุปแบบ invoice: ช่วงวันรับ–คืนและจำนวนวัน ลูกค้า การ์ดสินค้าพร้อมรูป/สี/ไซซ์/จำนวน/ค่าเช่า/ค่าประกันและป้ายคิว การรับและชำระเงิน และสรุปยอดเช่า ส่วนลดค่าเช่า ค่าเช่าสุทธิ ยอดรวมค่าประกัน ส่วนลดค่าประกัน ค่าประกันสุทธิ ค่าจัดส่ง และยอดรวมทั้งหมด ปุ่มนี้ใช้ได้เมื่อไม่มีข้อมูลค้างบันทึกและมีสินค้าในตะกร้า ระบบรวมตะกร้ากับวันที่ ส่วนลด และหมายเหตุของร่างล่าสุดเป็นบิลเดียว ส่วนลดแสดงอย่างเดียว (แก้ที่ร่างล่าสุด) กรอกค่าส่ง วิธีชำระ แล้วกด **ตรวจคิวและเตรียมบิลให้ตรวจ** ระบบตรวจ catalog/ราคา/คิวซ้ำและสร้างใบตรวจอายุ 5 นาที ยังไม่สร้างออเดอร์ใน Alex
7.1 วิธีชำระค่าเช่า/ค่าประกันไม่บังคับ ใช้ตัวเลือกเดียวกับ Alex (ยังไม่ชำระ, เงินสด, โอนเงิน, Alipay/wechat, บัตรเครดิต, ช่องทางอื่น) เริ่มต้น **ยังไม่ชำระ** ค่าจัดส่งที่มากกว่า 0 ถูกเขียนต่อท้ายหมายเหตุของออเดอร์ใน Alex อัตโนมัติ (Alex ไม่มีช่องค่าส่ง) ไม่ต้องติ๊กรับทราบ หน้าต่างใบสรุปเลื่อนดูได้ในตัวเองโดยหน้าเบื้องหลังไม่เลื่อน
8. อ่านรายละเอียดและติ๊กยืนยัน แล้วกด **ส่งสร้างบิล / ออเดอร์ใน Alex** ระบบตรวจต้นฉบับและคิวอีกครั้งก่อน POST จริง ผลและประวัติอยู่ในแท็บนี้ การ **อนุมัติร่างภายใน** เป็นการเก็บร่างในระบบเดิม แยกจากการส่งบิลเข้า Alex
8.1 ถ้าตอนเตรียมบิล Alex แจ้งว่าสินค้า **ติดคิว** หรือ **ตรวจคิวไม่ได้** ใบตรวจยังสร้างได้ และแสดงรายการที่ติด พร้อม checkbox **ทราบว่าติดคิว ตกลงส่งออเดอร์เข้า Alex ต่อ** ปุ่มส่งจะเปิดเมื่อติ๊กทั้งช่องนี้และช่องยืนยันข้อมูล บิลที่ส่งแบบนี้บันทึก `queue_accepted` และผลคิวตอนส่งไว้ ถ้าคิวเปลี่ยนเป็นติดหลังเตรียมบิล ระบบจะไม่ส่งและให้เตรียมบิลใหม่ (`QUEUE_BLOCKED`) ยังไม่ได้ทดสอบกับ Alex จริงว่า Alex รับหรือปฏิเสธออเดอร์ที่ติดคิว
9. แท็บ **เวอร์ชันก่อนหน้า** แสดงทุกเวอร์ชันพร้อมสถานะ:
   - **✅ ส่งเข้า Alex แล้ว** (พื้นเขียว) — มีบิลที่ส่งจากเวอร์ชันนี้ (ยืนยันแล้ว หรือส่งแล้วแต่ยังไม่ได้เลขออเดอร์) แสดงเลขออเดอร์ถ้ามี งานปิดแล้ว แก้ไขและส่งซ้ำไม่ได้ ร่างล่าสุดที่ส่งแล้วจะถูกล็อกพร้อมปุ่มโคลน
   - **ยังไม่ส่ง** — แก้ไขและส่งได้ · **ยกเลิกแล้ว** — ยกเลิกได้ทุกเวอร์ชันและย้อนกลับไม่ได้ (ยกเลิกเฉพาะในระบบนี้ บิลใน Alex ต้องยกเลิกใน Alex เอง)
   - **แก้ไข** (เฉพาะยังไม่ส่ง) หยิบเวอร์ชันนั้นขึ้นมาเป็นร่างล่าสุด · **โคลน** (ทุกสถานะ) คัดลอกเป็นเวอร์ชันใหม่ ทั้งสองแบบสร้างเวอร์ชันใหม่และคืนตะกร้าของเวอร์ชันนั้น: เวอร์ชันที่ส่งแล้วใช้รายการในบิล, ร่างล่าสุดที่ยังไม่ส่งใช้ตะกร้าปัจจุบัน, เวอร์ชันอื่นใช้ตะกร้าที่บันทึกพร้อมเวอร์ชัน (เวอร์ชันที่บันทึกก่อนอัปเดตนี้และยังไม่ส่งไม่มีตะกร้าเก็บไว้ ตะกร้าปัจจุบันคงเดิม) ค่าที่ต่างจากช่องที่เคยยืนยันไม่ถูกนับเป็นข้อขัดแย้งเพราะแอดมินเลือกเวอร์ชันเอง
   - บิลของเวอร์ชันอื่นไม่ล็อกการส่งเวอร์ชันใหม่ ผลเช็คคิวทำหน้าที่กันจองซ้ำแทน (ถ้าบิลก่อนสร้างใน Alex แล้ว Alex จะแจ้งว่าติดคิว) ล็อกเหลือเฉพาะช่วงที่กำลังส่งจริงเพื่อกันกดซ้ำ

## ภาพตัวอย่างและข้อมูลที่ต้องตรวจ

- **nina — dark brown — M:** 3 วันเป็นระยะเช่า ค่าเช่า 550 บาท ค่าส่ง Flash 40 บาท เข็มกลัดดอกไม้อยู่ในหมายเหตุ “รับชุด 5,6” ยังไม่ใช่วันรับที่แน่นอน วันส่ง 4/11 ไม่ใช่วันรับชุด จึงไม่ถูกบันทึก
- **Haatiya — Blush Pink:** ชื่อตัวใหญ่บนโปสเตอร์ (Haatiya) คือ **ประเภท (category) ของ Alex ไม่ใช่ชื่อสินค้า** AI ใส่ไว้ที่ `category` แล้ว backend เรียก `GET /api/category` เพื่อหา code ของประเภท (เทียบชื่อ `description` หรือ `code` เฉพาะที่ `state=true`) แล้วค้น `GetProductItems` ด้วย `category=<code>` กับสี/ไซซ์ ถ้าไม่พบประเภทจะค้นด้วยชื่อแทนและถามให้ตรวจ · ข้อความจองเลือก M แม้โปสเตอร์มี S,M จึงไม่เพิ่มจำนวนเป็นสองชุด รับ 12/11 คืน 15/11 ใช้ปีปัจจุบันเมื่อไม่ได้ระบุปี (วันใช้งาน 14/11 ไม่ถูกบันทึก) ตารางราคา 1/3/5 วันยังไม่ใช่ยอดที่ตกลง ให้แอดมินเลือกยอดจริง
- หากสองชุดใช้คนละช่วงวัน จะได้สองกลุ่มบิล ข้อมูลร่วมใช้เฉพาะช่องที่รายการนั้นยังไม่ได้ระบุ รูปซ้ำไม่เพิ่มจำนวนชุดอัตโนมัติ
- ไม่ใช้ชื่อชุดหรือผล AI เป็น Product ID ต้องค้นและยืนยันสินค้าจริงจาก Alex ก่อน

## ข้อตกลง API และการตั้งค่า

ใช้บัญชีและขอบเขตจาก [คู่มือ Step 3](step-3-products.md) และ config ฝั่ง server เท่านั้น ไม่มี token หรือรหัสผ่านใน frontend

- `POST /api/orderdetail/checkq`: ส่ง array ทีละรายการ `{productItemId,pickupDate,returnDate,branchId,qty}` อ่าน `result=1` ว่าง, `0` ไม่ว่าง; HTTP/schema ผิดหรือค่าอื่นเป็น “ยังตรวจไม่ได้” ส่งบิลได้เมื่อแอดมินติ๊กยืนยันส่งทั้งที่ติดคิว (`accept_queue`) รองรับวันที่ตอบกลับ `YYYY-MM-DDT00:00:00` ที่ตรวจพบใน API จริง
- เวอร์ชันร่าง: `POST /api/inquiries/{id}/drafts/{draft}/copy` (`mode`: `edit` เฉพาะเวอร์ชันที่ยังไม่ส่ง / `clone` ทุกเวอร์ชัน) และ `POST /api/inquiries/{id}/drafts/{draft}/cancel` · `GET /api/inquiries/{id}/drafts` คืน `state` (`OPEN`/`SENT`/`CANCELLED`) และ `bill` ต่อเวอร์ชัน · เวอร์ชันที่ปิดแล้วเตรียม/ส่งบิลไม่ได้ (`DRAFT_CLOSED`) บิลบันทึก `draft_id`/`draft_version` บิลเก่าก่อนอัปเดตนี้นับเป็นของเวอร์ชันล่าสุดที่บันทึกก่อนเวลาส่ง
- `POST /api/v2/AddRentalOrder`: สร้างตาม `prompts/orderheader_create.json` และใช้รายการที่ยืนยันแล้ว `rentalDiscount`/`bailDiscount` มาจากช่องส่วนลดค่าเช่า/ส่วนลดค่าประกันที่แอดมินกรอก (สตางค์) หรือเมื่อเว้นว่างคือ ยอดแค็ตตาล็อกของตะกร้า − ราคาที่แจ้งลูกค้า (ไม่ต่ำกว่า 0) ไม่รองรับส่วนลดติดลบหรือเกินยอดแค็ตตาล็อก ไม่มีการใส่วันเกิดสมมติหรือเปิดโปรโมชั่นเอง
- template นี้ไม่มีช่องค่าจัดส่งแยก เมื่อมีค่าส่ง ระบบต้องให้แอดมินรับทราบก่อนบันทึกเป็นหมายเหตุ **ยอดค่าเช่าใน Alex ไม่รวมค่าส่ง** หากต้องการรวมเป็นยอดเรียกเก็บแยก ต้องเพิ่ม contract ค่าส่งที่ Alex รองรับก่อน
- ตัวอย่างสองไฟล์ที่ได้รับเป็น request จึงยังไม่ยืนยันชื่อฟิลด์เลขบิลใน response ตั้ง `ALEX_ORDER_ID_POINTER` ใน `.env` บน server **หลังตรวจ response สร้างสำเร็จจริงแล้วเท่านั้น** เช่น `/orderId` หรือ `/data/orderId` ตามข้อมูลจริง; `$` ใช้เฉพาะเมื่อ response สำเร็จเป็นเลข/ข้อความ ID โดยตรง ตัวอย่างเหล่านี้ไม่ใช่ schema ที่ตรวจยืนยันแล้ว
- ค่าเริ่มต้น `ALEX_ORDER_ID_POINTER` ว่าง: ส่งคำขอได้ แต่บิลจะขึ้น “ส่งแล้ว · ยังไม่ได้เลขออเดอร์” จนแอดมินตรวจใน Alex และบันทึกเลขออเดอร์ (ไม่บังคับ และไม่ล็อกการส่งเวอร์ชันอื่น) ระบบไม่ใช้เพียง HTTP 2xx ยืนยันว่ามีบิล

## ผลตอบกลับไม่ชัดเจนและการส่งซ้ำ

คำขอส่งบิลมี ID คงที่ บันทึกก่อน POST และส่งเพียงครั้งเดียว การกดซ้ำด้วย ID เดิมอ่านผลเดิม แต่ละเวอร์ชันส่งได้ครั้งเดียว (ตรวจภายใต้ล็อกของ inquiry ระหว่างส่ง กันสองหน้าต่างส่งเวอร์ชันเดียวกัน) ระบบกู้สถานะหลังรีสตาร์ตและอ่านประวัติได้แม้แชทหรือร่างเปลี่ยนไป

หาก timeout, HTTP error, หรืออ่านเลขบิลไม่ได้ จะเก็บ `SUBMIT_UNKNOWN` ไม่ส่งซ้ำ และนับว่าเวอร์ชันนั้นส่งแล้ว ล็อกของ inquiry ปลดทันทีที่ Alex ตอบ (เดิมล็อกจนแอดมินบันทึกผล) ตรวจใน Alex แล้วกด **บันทึกผลที่ตรวจจาก Alex** ได้: ถ้าพบ ให้กรอกเลขออเดอร์; ถ้าไม่พบ ต้องรออย่างน้อย 2 นาทีจากการส่งครั้งล่าสุดและตรวจ Alex ก่อนยืนยันว่าไม่ได้สร้าง (เวอร์ชันกลับเป็นยังไม่ส่ง) ถ้าจะส่งออเดอร์เดิมซ้ำ ให้โคลนเวอร์ชันแล้วส่ง โดยผลเช็คคิวจะเตือนถ้าบิลแรกสร้างใน Alex แล้ว · `active` ในบิลหมายถึงกำลังส่งเท่านั้น ตอน startup ระบบเคลียร์ `active` ของบิลที่ Alex ตอบแล้ว

ระบบไม่รับประกันการกันคิวระหว่างผลตรวจและการสร้างบิล หากมีผู้ใช้อื่นจองพร้อมกัน ผลสุดท้ายขึ้นกับ Alex

## ข้อมูลและการทดสอบ

รูปภายในเก็บ GridFS ตามอายุ `LINE_MEDIA_RETENTION_DAYS` และต้องล็อกอินเพื่อเปิด ใช้รวมกับรูปจากแชทไม่เกิน 8 MB ต่อการส่ง AI; browser ลดภาพเหลือด้านยาว 2,000 px และไม่เกินประมาณ 1.4 MB ต่อรูป ข้อมูลลูกค้าต้องมีหลักฐานข้อความลูกค้าตรงตัวและตรวจ context ใหม่ก่อนเติม

collections ใหม่: `inquiry_attachments`, `availability_checks`, `bill_reviews`, `alex_submissions`; มี index แยก shop/channel/inquiry และ unique reservation เฉพาะบิลที่กำลังส่ง (active) · `order_drafts` เก็บ `cart` ที่บันทึกพร้อมเวอร์ชัน, `copied_from`, `cancelled_at`/`cancelled_by` MCP ยังคงมีเพียงเครื่องมือค้นหาแบบอ่านข้อมูล ไม่เพิ่มเครื่องมือสร้างบิล

ทดสอบ API ด้วย MongoDB disposable: `cargo test -- --include-ignored` และ `TEST_MONGODB_URI` ที่ชี้ฐานทดสอบ การทดสอบสร้างบิลใช้ Alex จำลองเท่านั้น ส่วน production ทดสอบอ่าน login/catalog/checkq โดยไม่สร้างบิลจริง

## Build และ deploy

Windows build บน local เท่านั้น ใช้ `build-backend.bat` และ `build-frontend.bat` แล้วผู้ใช้รัน `rungit.bat "เพิ่มสรุปจากรูปและสร้างบิล Alex"` เอง เมื่อมี release พร้อมแล้ว ไม่ต้อง build โปรแกรมซ้ำบน Ubuntu

Ubuntu:

```sh
ssh Hermes
cd ~/alex-connectingpoint
bash ./loadgit.sh main
sudo bash ./docker-build.sh --full-stack
sudo bash ./docker-deploy.sh --full-stack
```

หากแก้เฉพาะ `.env` บน server ให้รันเฉพาะ deploy คำสั่งสุดท้าย ตรวจ credentials/branch และ extraction profile Hermes ตามคู่มือ Step 2/3 ก่อนใช้งานจริง
