# สรุปจากรูป → ร่างออเดอร์และตะกร้า → เช็คคิว → สร้างบิลใน Alex

เงื่อนไขเพิ่มเติมของร้านตั้งได้จากไอคอนเฟืองบนการ์ดชื่อร้านในหน้า Home โดยเจ้าของร้าน เช่น คำนำหน้าชื่อลูกค้า ค่าขนส่งจากรหัสสินค้าตามยอดเช่าสุทธิ และใช้ค่าเช่า/ค่าประกันจากสรุปบิลเป็นหลักแทนการคำนวณจากตะกร้า ระบบตรวจรูปแบบก่อนให้ AI อ่านและบังคับกฎด้วย server ก่อนสร้างบิล ดู [คู่มือเงื่อนไข AI สำหรับออกบิล](shop-billing-instructions.md)

## การใช้งาน
การกดรายการ **สิ่งที่ลูกค้าขอจากรูป/สรุป** จะเติมโหมดค้น ชื่อ/รหัส แบรนด์ สี และไซซ์จากรายการนั้น แม้ค้นสินค้าใน Alex ยังไม่พบ โดยผลค้นที่บันทึกไว้จะไม่ล้างข้อมูลที่เพิ่งเติม ช่อง **แบรนด์** พิมพ์ชื่อหรือรหัสเพื่อแสดงเฉพาะชื่อใกล้เคียงได้ รวมคำที่สะกดคลาดเคลื่อนเล็กน้อย และเลือกด้วยลูกศร/Enter หรือแตะรายการ รองรับชื่อปนรุ่น เช่น `Blush Garden - Long Dress 20` → แบรนด์ `Blush Garden`; ถ้ามีหลายชื่อใกล้เคียงพอกันจะให้แอดมินเลือก กดล้างแบรนด์เพื่อค้นใหม่หรือค้นทุกแบรนด์

ไซซ์ใช้ค่าที่ตกลงแล้วในสรุปแอดมิน หรือการยืนยัน/แก้ไขล่าสุดในแชทของ inquiry ปัจจุบันทั้งลูกค้าและแอดมิน พร้อมข้อความอ้างอิง หากมีหลายชุดต้องระบุว่าเป็นไซซ์ของชุดใด ไม่ใช้คำถามเปรียบเทียบไซซ์ ขนาดร่างกาย ตัวเลขรุ่นชุด หรือไซซ์ที่มีในสต็อกมาเดาแทน เมื่อไม่ชัดเจนจะเว้นไว้และถามให้ยืนยัน ร่างเดิมที่ยังไม่มีไซซ์ให้เตรียมออเดอร์ด้วย AI ใหม่เพื่ออ่านข้อมูลยืนยันล่าสุด

เมื่อกด **เตรียมออเดอร์ด้วย AI** ปุ่มจะแสดงพวงดาวหมุนและข้อความกำลังเตรียมออเดอร์และข้อมูลลูกค้า ตั้งแต่บันทึกสรุป เข้าคิว จน AI ทำงานเสร็จ ระหว่างนี้กดซ้ำไม่ได้ เมื่อเสร็จจะเปิดร่างล่าสุดให้แอดมินตรวจ ชื่อ เบอร์โทร และที่อยู่ที่เติมจากแชทต้องมีข้อความลูกค้าอ้างอิง หากไม่พบจะไม่เดาข้อมูลหรือหยิบจาก LINE display name/โปรไฟล์เก่า ข้อความที่ส่งมาใหม่หรือถูก unsend ระหว่างทำงานจะทำให้ร่างนั้นไม่ถูกบันทึก ต้องเตรียมใหม่จากบริบทล่าสุด

1. เลือก inquiry และเปิด **สรุปแอดมิน** กด **แนบรูป** ได้รวมสูงสุด 5 รูปต่อร่าง (รูปที่แนบลบได้ด้วยปุ่ม 🗑 มุมรูป ระบบลบไฟล์และเอาออกจากรูปที่เลือกในสรุป ร่างเดิมต้องเตรียมใหม่เหมือนตอนแนบรูปเพิ่ม) รวมรูปที่เลือกจากแชทด้วย เขียนคำบรรยายเพิ่มได้แต่ไม่บังคับ วันที่ที่มีวันและเดือนชัดเจนแต่ไม่ระบุปีจะใช้ปีปัจจุบันตามเวลาไทย ณ เวลาสร้างคำขอ AI (วันรับชุดและวันคืนชุดของออเดอร์ — Alex ใช้เพียงสองวันนี้ ไม่มีช่องวันใช้งานหรือวันส่งชุด หากรูปมีวันต่างกัน AI จะถามว่าจะแยกออเดอร์หรือไม่) หากระบุปีไว้จะใช้ปีนั้นและแปลง พ.ศ. เป็น ค.ศ. รูปแนบส่วนนี้เป็นข้อมูลภายใน ไม่ถูกส่งให้ลูกค้าทาง LINE
1.1 คำบรรยายวางเป็น **สรุปบิล** ที่แอดมินส่งลูกค้าได้ (ตัวอย่างใน `prompts/ai-order-summary-ex.md`) ถ้าส่งบิลในแชทไปแล้ว กด **ใช้สรุปบิลล่าสุดจากแชท** เพื่อคัดลอกข้อความล่าสุดของแอดมินที่มีทั้ง "ค่าเช่า" และ "ค่าประกัน" มาใส่ช่องนี้ (ถามก่อนแทนข้อความเดิม) AI อ่านข้อมูลรายการจากสรุปและรูปที่เลือก ส่วนชื่อ เบอร์โทร และที่อยู่จะอ่านจากข้อความลูกค้าใน inquiry ปัจจุบันเพิ่มเติม โดยให้ค่าที่ลูกค้าแก้ไขล่าสุดมีความสำคัญก่อน กติกาที่ AI ใช้อ่านบิล:
   - บรรทัด `ชื่อ <ประเภท> / <ชื่อชุด> - <สี> / size <ไซซ์> / <N> วัน` = 1 รายการ (หลายบรรทัด = หลายรายการ) คำว่า "ชื่อ" ตรงนี้คือ **ประเภท (category) ของ Alex ไม่ใช่ชื่อลูกค้า** ส่วนหน้า " - " เป็นคำค้นชื่อชุด ส่วนหลังเป็นสีตามที่เขียน "N วัน" เป็นระยะเช่า ไม่ใช่จำนวนชิ้นและไม่ใช้คำนวณวันที่
   - `ค่าเช่า`/`ค่าประกัน` = ราคาที่แจ้งลูกค้า (ยอดรวมทั้งออเดอร์) · `ค่าส่ง` หรือยอดในบรรทัด `จัดส่งชุด` (เช่น `flash 40-.`) = ค่าจัดส่ง, `ฟรี` = 0 · `รวมยอดโอนทั้งหมด` ไม่ถูกบันทึก
   - `ลูกค้ารับชุด` = วันรับ, `ส่งคืนชุด` = วันคืน (เวลา "ขนส่งก่อน 16:00 น." ลงหมายเหตุ) ปีสองหลักหลังชื่อเดือนไทย เช่น `พ.ย 69` คือ พ.ศ. 2569 = ค.ศ. 2026 · `ใช้งานชุด` ลงหมายเหตุตามที่เขียน · วันในบรรทัด `จัดส่งชุด` เป็นวันร้านส่งของ ไม่ใช่วันรับ
   - ข้อความ emoji ของ LINE เช่น `(blue dot dress)` เงื่อนไขร้าน (ชำระภายใน…, ค่าเปลี่ยนชุด, ปรับส่งคืนช้า, ขนส่งที่รับคืน J&T/EMS/DHL) และเลขบัญชี/ชื่อบัญชีของร้าน ไม่ถูกใช้เป็นข้อมูลออเดอร์หรือลูกค้า
2. กด **เตรียมออเดอร์ด้วย AI** ระบบอ่านเฉพาะรูปที่เลือกและสรุปแอดมิน ไม่ส่งแชทหรือร่างเก่าให้ AI กวาดออเดอร์/สินค้า จากนั้น backend ล็อกอิน Alex แล้วค้น `POST /api/v2/GetProductItems` ด้วยชื่อหรือรหัส สี และไซซ์ที่สกัดได้ เมื่อพบตรงกันรายการเดียวจะเติมรหัส ชื่อ สี ไซซ์ลงรายการที่ลูกค้าขอพร้อมหลักฐาน ราคาแค็ตตาล็อกอยู่ในตะกร้า ไม่คัดลอกลงร่าง ถ้ามีประเภทแต่ค้นชื่อชุดในประเภทนั้นไม่พบ ระบบแสดงสินค้าทั้งประเภท (ตามสี/ไซซ์ถ้ามี) ให้เลือกแทน และไม่เลือกให้เอง
3. เปิด **ร่างล่าสุด** ซึ่งเป็นหน้าออเดอร์เดียว (ไม่มีแท็บเลือกชุดและแท็บลูกค้าแล้ว): ส่วน **ลูกค้า** จะแสดงชื่อ เบอร์ และที่อยู่ที่ AI พบจากแชทพร้อมข้อความอ้างอิงตั้งแต่กดเตรียมออเดอร์แล้ว สามารถกด **ค้นข้อมูลลูกค้าจากแชท** เพื่อค้นซ้ำและเติมข้อมูลเพิ่มเติมได้ ช่องที่ไม่พบคงค่าเดิม เบอร์โทรถูกตัดช่องว่างและขีดกลางเสมอ (เช่น `081-234 5678` → `0812345678`) ทั้งในร่างและบิล Alex
4. ส่วน **ค้นหาชุดจาก Alex** มีตัวกรองชื่อ/รหัส/ลิงก์/รูป สี ไซซ์ หมวดหมู่ ลาย ผลค้นหาแสดงรูปจาก Alex ชื่อ รหัส ราคา ค่าประกัน กด **เพิ่มลงตะกร้า** ชิปด้านบนคือสิ่งที่ลูกค้าขอจากรูป/สรุป กดเพื่อดูผลค้นอัตโนมัติจากข้อ 2 หรือเติมคำค้นให้ ระบบไม่เลือกสินค้าเอง
5. ส่วน **ตะกร้าสินค้า** แสดงการ์ดแบบตะกร้า Alex ปรับจำนวนด้วย −/+ (1–999) หรือ **เอาออก** ตะกร้าผูกกับ inquiry และบันทึกทันที การบันทึกร่างเวอร์ชันใหม่ไม่ล้างตะกร้า สินค้าทุกชิ้นต้องอยู่สาขาเดียวกัน
6. ส่วน **วันรับ–คืนชุด**, **ส่วนลดและค่าจัดส่ง** และ **หมายเหตุ** ใช้กับทั้งออเดอร์ (1 inquiry = 1 ออเดอร์ ไม่ใช่ต่อสินค้า) วันที่ทุกชุดที่ AI อ่านได้จากรูป/สรุปแสดงเป็นปุ่ม **วันที่อ่านได้จากรูป/สรุป** กดเพื่อใส่วันรับ/คืน (รูปที่วันต่างกันหรือรับ 5,6 จะได้หลายตัวเลือก ระบบไม่เลือกเอง) **วิธีมารับ** เลือกจากตัวเลือกเดียวกับ Alex (มารับเอง, Line Man, Grab, Kerry, Flash, ขนส่งอื่น) เริ่มต้นเป็น Flash ไม่มีช่องขนส่งและช่องส่งคืนก่อนเวลาแยก (เวลาส่งคืนอยู่ในหมายเหตุ ขนส่งที่ไม่อยู่ในรายการเป็น ขนส่งอื่น และเก็บชื่อไว้ในหมายเหตุ) หลังกดเช็คคิว การ์ดในตะกร้าแสดงป้าย **ติดคิว** สีแดงหรือ **ว่าง** สีเขียว ส่วนลดค่าเช่า/ส่วนลดค่าประกันห้ามเกินยอดแค็ตตาล็อกของตะกร้า ถ้าเว้นว่าง ระบบคิดส่วนลดให้จากราคาที่แจ้งลูกค้าเทียบกับราคาใน Alex ของตะกร้า (เช่น แจ้งค่าเช่า 500 แต่ Alex 700 → ส่วนลดค่าเช่า 200; ค่าประกันคิดแบบเดียวกัน) ช่องแสดงค่า "อัตโนมัติ" ไว้ กรอกตัวเลขเพื่อแทน หรือกรอก 0 ถ้าไม่ให้ส่วนลด ถ้าราคาที่แจ้งสูงกว่า Alex จะขึ้นคำเตือนและบิลใช้ราคา Alex (Alex ไม่มีช่องบวกเพิ่ม) กด **เช็คคิวจาก Alex** ได้ทันทีด้วยวันที่บนหน้าจอ (อ่านอย่างเดียว ไม่กันคิว) แล้วกด **บันทึกร่างเป็นเวอร์ชันใหม่**
7. หลังบันทึกร่าง กด **สรุปออเดอร์และส่งเข้า Alex** ท้ายแท็บ **ร่างล่าสุด** เพื่อเปิด modal สรุปลูกค้า สินค้า วันรับ–คืน การรับและชำระเงิน และยอดรวม ปรับข้อมูลลูกค้า หมายเหตุ และส่วนลดค่าเช่า/ค่าประกันได้ที่นี่ ส่วนลดที่แอดมินแก้เป็นยอดสุดท้าย ไม่บวกส่วนลดเก่าหรือโปรโมชั่นส่วนลดเพิ่ม ไม่มีช่องค่าจัดส่งแยกหรือวันเกิด ค่าขนส่งเป็นสินค้ารายการหนึ่งในตะกร้าและไม่ใช่ฐานส่วนลด
7.1 วิธีชำระค่าเช่า/ค่าประกันใช้ตัวเลือกของ Alex บิลใหม่เริ่มต้น **ยังไม่ชำระ** หากไม่มีสลิปที่เข้าเกณฑ์ เมื่อแก้ใน modal จะบันทึกอัตโนมัติ และรอบันทึกให้เสร็จก่อนปิดหรือส่ง ข้อมูลแยกตามร้าน ลูกค้า ร่าง และกลุ่มบิล พร้อม revision ป้องกันเขียนทับการแก้ของอีกคน หากบันทึกไม่สำเร็จ modal จะเก็บค่าที่กรอกไว้ให้ลองใหม่ เมื่อเปิดอีกครั้งจะใช้ค่าที่บันทึกไว้ ไม่กลับไปเป็นค่าเริ่มต้น หมายเหตุที่แอดมินบันทึกในร่างจะตามมาใน modal ส่วนข้อความจาก AI ที่ยังไม่ได้บันทึกยืนยันจะไม่ถูกเติมเอง หากแอดมินแก้หรือล้างหมายเหตุใน modal ให้ใช้ค่าจาก modal เป็นอันดับแรก
7.2 แท็บ **สรุปบิลล่าสุด** แสดงข้อมูลที่บันทึกจาก modal ก่อนส่งแบบอ่านอย่างเดียว รวมวิธีชำระ หมายเหตุ ส่วนลด และยอดรวม หลังส่งจะอ่าน snapshot ของคำขอที่ส่งจริง พร้อม Order ID และ Order Number ที่ตอบกลับ โดยผูกกับลูกค้าและร่างต้นฉบับ แชทหรือร่างที่เปลี่ยนภายหลังไม่ทำให้สรุปบิลที่ส่งแล้วหายไป
8. ตรวจใน modal แล้วกด **ส่งออเดอร์เข้า Alex** ครั้งเดียว ระบบบันทึกค่าที่แก้ ตรวจ catalog/ราคา/คิว และส่งต่อ ไม่มี checkbox หรือหน้าขอยืนยันซ้ำ ระหว่างส่งปุ่มถูกปิด หลังได้ผลจะเปิดแท็บ **สรุปบิลล่าสุด** หากเครือข่ายขัดข้อง ค่าที่กรอกยังอยู่และลองส่งด้วย review ID เดิมได้ Backend ยังคงตรวจต้นฉบับ สิทธิ์ คิว และป้องกันสร้างบิลซ้ำ
8.1 ถ้า Alex แจ้งว่าสินค้า **ติดคิว** หรือ **ตรวจคิวไม่ได้** ระบบจะแสดงรายการและหยุดก่อนส่ง ปุ่มเดิมเปลี่ยนเป็น **ส่งออเดอร์เข้า Alex แม้ติดคิว** หรือ **แม้ยังตรวจคิวไม่ได้** ผู้จัดการหรือเจ้าของร้านเลือกส่งต่อได้โดยไม่ต้องติ๊ก checkbox ระบบตรวจคิวใหม่และบันทึก `queue_accepted` พร้อมผลคิวตอนส่ง ถ้าคิวเปลี่ยนเป็นติดระหว่างตรวจและส่ง ระบบยังหยุดด้วย `QUEUE_BLOCKED` ยังไม่ได้ทดสอบกับ Alex จริงว่า Alex รับหรือปฏิเสธออเดอร์ที่ติดคิว
9. แท็บ **เวอร์ชันก่อนหน้า** แสดงทุกเวอร์ชันพร้อมสถานะ:
   - **✅ ส่งเข้า Alex แล้ว** (พื้นเขียว) — มีบิลที่ส่งจากเวอร์ชันนี้ (ยืนยันแล้ว หรือส่งแล้วแต่ยังไม่ได้เลขออเดอร์) แสดงเลขออเดอร์ถ้ามี งานปิดแล้ว แก้ไขและส่งซ้ำไม่ได้ ร่างล่าสุดที่ส่งแล้วจะถูกล็อกพร้อมปุ่มโคลน
   - **ยังไม่ส่ง** — แก้ไขและส่งได้ · **ยกเลิกแล้ว** — ยกเลิกได้ทุกเวอร์ชันและย้อนกลับไม่ได้ (ยกเลิกเฉพาะในระบบนี้ บิลใน Alex ต้องยกเลิกใน Alex เอง)
   - **แก้ไข** (เฉพาะยังไม่ส่ง) หยิบเวอร์ชันนั้นขึ้นมาเป็นร่างล่าสุด · **โคลน** (ทุกสถานะ) คัดลอกเป็นเวอร์ชันใหม่ ทั้งสองแบบสร้างเวอร์ชันใหม่และคืนตะกร้าของเวอร์ชันนั้น: เวอร์ชันที่ส่งแล้วใช้รายการในบิล, ร่างล่าสุดที่ยังไม่ส่งใช้ตะกร้าปัจจุบัน, เวอร์ชันอื่นใช้ตะกร้าที่บันทึกพร้อมเวอร์ชัน (เวอร์ชันที่บันทึกก่อนอัปเดตนี้และยังไม่ส่งไม่มีตะกร้าเก็บไว้ ตะกร้าปัจจุบันคงเดิม) ค่าที่ต่างจากช่องที่เคยยืนยันไม่ถูกนับเป็นข้อขัดแย้งเพราะแอดมินเลือกเวอร์ชันเอง
   - บิลของเวอร์ชันอื่นไม่ล็อกการส่งเวอร์ชันใหม่ ผลเช็คคิวทำหน้าที่กันจองซ้ำแทน (ถ้าบิลก่อนสร้างใน Alex แล้ว Alex จะแจ้งว่าติดคิว) ล็อกเหลือเฉพาะช่วงที่กำลังส่งจริงเพื่อกันกดซ้ำ

## สถานะการส่งเข้า Alex

- เมื่อกดส่ง จะแสดงขั้นตอนบันทึกข้อมูล ตรวจราคา/คิว และส่งเข้า Alex ใกล้ปุ่มส่ง ถ้ารอนานกว่า 20 วินาทีมีข้อความแจ้งว่ากำลังรอผล โดยไม่ล้างฟอร์ม
- **ส่งสำเร็จ:** ต้องได้สถานะ CONFIRMED พร้อม Order ID จึงแสดงข้อความยืนยันและ Order Number/Order ID เปิดสรุปบิลล่าสุดพร้อมแจ้งผลบนหน้าจอ 10 วินาที สถานะและเลขออเดอร์ยังอยู่ในสรุปบิลหลังข้อความแจ้งผลปิด
- **ส่งไม่สำเร็จ:** บันทึก/ตรวจข้อมูลไม่ผ่าน หรือระบบยืนยัน NOT_CREATED จะแจ้งเหตุผลและคง modal กับค่าที่กรอกไว้ กดลองส่งอีกครั้งได้หลังตรวจข้อมูล การส่งใหม่จาก NOT_CREATED ใช้ review ใหม่
- **ยังยืนยันไม่ได้:** หากส่งคำขอไปแล้วแต่เครือข่ายหลุด หมดเวลา หรือไม่ได้ Order ID จะไม่แสดงว่าสำเร็จและไม่ปิด modal อัตโนมัติ ปุ่มตรวจผลล่าสุดอ่านประวัติอย่างเดียว ถ้าพบคำขอเดิมจะติดตามผลนั้น ถ้ายังไม่พบผล สามารถกดติดตามด้วยคำขอเดิมเพื่อใช้ review ID เดิมได้ ไม่สร้างรหัสใหม่หรือส่งซ้ำอัตโนมัติ
- จำรหัสคำขอ เวอร์ชันร่าง และการยอมรับคิวไว้ใน sessionStorage ของแท็บ ไม่เก็บข้อมูลลูกค้าหรือ token เมื่อรีเฟรชจะกลับมาตรวจคำขอของร่างเดิม แยกตาม inquiry และลบตัวช่วยติดตามเมื่อยืนยันสำเร็จหรือยืนยันว่าไม่ได้สร้างบิล
- คำขอบันทึกฟอร์ม ตรวจบิล และส่งออเดอร์มีเวลารอสูงสุด 90 วินาทีต่อขั้นตอน การตรวจผลรอ 15 วินาที การหมดเวลาที่ browser ไม่ได้ยืนยันว่า Alex ยกเลิกงาน กรณี SUBMIT_UNKNOWN ต้องตรวจใน Alex และใช้ขั้นตอนบันทึกผลตรวจเดิมก่อนสร้างคำขอใหม่

## การอ่านสลิปโอนเงิน

- แนบสลิปในสรุปแอดมิน หรือเลือกรูปสลิปจากแชท แล้วกด **เตรียมออเดอร์ด้วย AI** พร้อมข้อมูลสรุปออเดอร์ รูปที่ไม่ได้เลือกและข้อความอ้างว่าโอนแล้วไม่ถือเป็นหลักฐานสลิป
- AI อ่านยอดโอนจริง สกุลเงิน ธนาคาร เลขอ้างอิง และข้อความโอนสำเร็จ ไม่ใช้ยอดเงินคงเหลือ ค่าธรรมเนียม ใบสั่งซื้อ หรือ QR ขอชำระเงิน เมื่ออ่านไม่ครบ โอนยังไม่สำเร็จ หรือไม่ใช่ THB จะไม่เติมวิธีชำระอัตโนมัติ
- ใช้ยอดค่าเช่าสุทธิรวมค่าประกันสุทธิหลังส่วนลดล่าสุดที่แอดมินแก้ ค่าขนส่งที่เป็นสินค้าอยู่ในยอดเดียวกับค่าเช่าตามปกติ หากผลต่างของสลิปกับยอดสุทธิไม่เกิน **100 บาท** ทั้งด้านมากกว่าหรือน้อยกว่า จะเติมค่าเช่าและค่าประกันเป็น **โอนเงิน** โดยไม่แก้ราคา ส่วนลด หรือหมายเหตุ และไม่รวมสลิปหลายใบเข้าด้วยกัน
- เมื่อแก้ส่วนลดจนสลิปไม่ตรงเกณฑ์ จะหยุดใช้การเติมอัตโนมัติ ส่วนวิธีชำระที่แอดมินเลือกเองคงเดิม รวมถึงเลือกยังไม่ชำระเอง หากต้องการกลับมาใช้สลิป กด **ใช้วิธีชำระโอนเงินจากสลิปที่ตรงกับยอดสุทธิ**
- ระบบตรวจหลักฐานกับร่างและยอดสุทธิอีกครั้งที่ server ก่อนบันทึก/ส่ง เก็บภาพอ้างอิง ยอด ธนาคาร และเลขอ้างอิงกับ snapshot ของบิล แสดงใน **สรุปบิลล่าสุด** สลิปที่ใช้เติมการชำระให้บิลเวอร์ชันก่อนแล้วจะไม่ใช้ซ้ำอัตโนมัติกับเวอร์ชันใหม่
- การอ่านจากภาพไม่ใช่การยืนยันธุรกรรมกับธนาคาร ฟีเจอร์นี้ไม่เชื่อม API ตรวจสลิปของธนาคาร แอดมินยังตรวจและแก้วิธีชำระก่อนส่งบิลได้

## ภาพตัวอย่างและข้อมูลที่ต้องตรวจ

- **nina — dark brown — M:** 3 วันเป็นระยะเช่า ค่าเช่า 550 บาท ค่าส่ง Flash 40 บาท เข็มกลัดดอกไม้อยู่ในหมายเหตุ “รับชุด 5,6” ยังไม่ใช่วันรับที่แน่นอน วันส่ง 4/11 ไม่ใช่วันรับชุด จึงไม่ถูกบันทึก
- **Haatiya — Blush Pink:** ชื่อตัวใหญ่บนโปสเตอร์ (Haatiya) คือ **ประเภท (category) ของ Alex ไม่ใช่ชื่อสินค้า** AI ใส่ไว้ที่ `category` แล้ว backend เรียก `GET /api/category` เพื่อหา code ของประเภท (เทียบชื่อ `description` หรือ `code` เฉพาะที่ `state=true`) แล้วค้น `GetProductItems` ด้วย `category=<code>` กับสี/ไซซ์ ถ้าไม่พบประเภทจะค้นด้วยชื่อแทนและถามให้ตรวจ · ข้อความจองเลือก M แม้โปสเตอร์มี S,M จึงไม่เพิ่มจำนวนเป็นสองชุด รับ 12/11 คืน 15/11 ใช้ปีปัจจุบันเมื่อไม่ได้ระบุปี (วันใช้งาน 14/11 ไม่ถูกบันทึก) ตารางราคา 1/3/5 วันยังไม่ใช่ยอดที่ตกลง ให้แอดมินเลือกยอดจริง
- หากสองชุดใช้คนละช่วงวัน จะได้สองกลุ่มบิล ข้อมูลร่วมใช้เฉพาะช่องที่รายการนั้นยังไม่ได้ระบุ รูปซ้ำไม่เพิ่มจำนวนชุดอัตโนมัติ
- ไม่ใช้ชื่อชุดหรือผล AI เป็น Product ID ต้องค้นและยืนยันสินค้าจริงจาก Alex ก่อน

## ข้อตกลง API และการตั้งค่า

ใช้บัญชีและขอบเขตจาก [คู่มือ Step 3](step-3-products.md) และ config ฝั่ง server เท่านั้น ไม่มี token หรือรหัสผ่านใน frontend

- `POST /api/orderdetail/checkq`: ส่ง array ทีละรายการ `{productItemId,pickupDate,returnDate,branchId,qty}` อ่าน `result=1` ว่าง, `0` ไม่ว่าง; HTTP/schema ผิดหรือค่าอื่นเป็น “ยังตรวจไม่ได้” ส่งบิลต่อได้เมื่อผู้มีสิทธิ์เลือกปุ่มส่งทั้งที่ติดคิว (`accept_queue`) รองรับวันที่ตอบกลับ `YYYY-MM-DDT00:00:00` ที่ตรวจพบใน API จริง
- เวอร์ชันร่าง: `POST /api/inquiries/{id}/drafts/{draft}/copy` (`mode`: `edit` เฉพาะเวอร์ชันที่ยังไม่ส่ง / `clone` ทุกเวอร์ชัน) และ `POST /api/inquiries/{id}/drafts/{draft}/cancel` · `GET /api/inquiries/{id}/drafts` คืน `state` (`OPEN`/`SENT`/`CANCELLED`) และ `bill` ต่อเวอร์ชัน · เวอร์ชันที่ปิดแล้วเตรียม/ส่งบิลไม่ได้ (`DRAFT_CLOSED`) บิลบันทึก `draft_id`/`draft_version` บิลเก่าก่อนอัปเดตนี้นับเป็นของเวอร์ชันล่าสุดที่บันทึกก่อนเวลาส่ง
- `POST /api/v2/AddRentalOrder`: สร้างตาม `prompts/orderheader_create.json` และใช้รายการที่ยืนยันแล้ว `rentalDiscount`/`bailDiscount` มาจากช่องส่วนลดค่าเช่า/ส่วนลดค่าประกันที่แอดมินกรอก (สตางค์) หรือเมื่อเว้นว่างคือ ยอดแค็ตตาล็อกของตะกร้า − ราคาที่แจ้งลูกค้า (ไม่ต่ำกว่า 0) ไม่รองรับส่วนลดติดลบหรือเกินยอดแค็ตตาล็อก ไม่มีการใส่วันเกิดสมมติหรือเปิดโปรโมชั่นเอง
- ค่าส่งที่เป็นสินค้าใน Alex ส่งใน `orderItems` ของออเดอร์เดียวกับชุด ยอดค่าเช่าใน Alex รวมราคาสินค้าค่าส่งหลังหักส่วนลดเฉพาะชุด เช่น ชุด 550 บาท + สินค้าค่าส่ง 40 บาท = 590 บาท ไม่มีส่วนลด 40 บาท และไม่คิดค่าส่งซ้ำจากยอดที่แจ้งในร่าง สินค้าค่าส่งระบุตามรหัสในกฎร้าน ชื่อสินค้าค่าส่ง หรือแอดมินเลือกป้าย **รายการค่าส่ง · ไม่คิดส่วนลด** ในตะกร้า ไม่เพิ่มสินค้าเองจากคำแนะนำ AI โหมด manual
- เก็บ `alex_order_id` และ `alex_order_number` แยกกันจากผลตอบของคำขอที่ส่ง พร้อม `inquiry_id`, `draft_id`, `draft_version`, `line_user_id`, `conversation_key` และ snapshot ลูกค้าที่ส่ง ไม่จับคู่จากชื่อหรือออเดอร์ล่าสุด ประวัติบิลและประวัติร่างแสดง Order ID/Order Number แยก label
- `POST /api/inquiries/{id}/checkout/submit` คืน `alex_order_id` และ `alex_order_number` จาก record ที่บันทึกแล้ว พร้อมรหัสลูกค้า/บทสนทนา/ร่างข้างต้น การติดตามคำขอเดิมคืน record เดิมและเลขเดิม ไม่สร้างออเดอร์ใหม่ ฟิลด์เลขทั้งสองมีเสมอ โดยเลขที่ Alex ยังไม่ส่งคืนเป็น `null` รวมถึงประวัติจาก release เก่า
- ถ้า Alex ยืนยันด้วย Order ID แต่ไม่คืน Order Number ระบบเก็บ Order ID และยังนับว่าออเดอร์สร้างแล้ว หน้าสรุปแจ้งชัดว่ายังไม่ได้รับ Order Number ให้ตรวจเลขใน Alex โดยไม่ส่งซ้ำ ไม่ใช้ Order ID เป็น Order Number และไม่เดาเลขจากบิลอื่น
- ถ้าไม่ตั้ง path ระบบอ่านฟิลด์ `orderId`/`OrderId`/`orderID`/`OrderID`/`order_id` กับ `orderNumber`/`OrderNumber`/`orderNo`/`OrderNo`/`order_number` จาก object เดียวที่ไม่กำกวมใน root, data, result, order หรือ orderDetail (รวม data/order และ data/orderDetail) ไม่ใช้ customerId/productItemId หรือฟิลด์ id ทั่วไปแทนเลขออเดอร์ หาก response ใช้ schema อื่น ตั้ง `ALEX_ORDER_ID_POINTER` และ `ALEX_ORDER_NUMBER_POINTER` ตามตัวอย่างตอบกลับจริง เช่น `/data/id` และ `/data/number`; `$` ใช้เลือก root scalar ที่ตรวจแล้ว รูปแบบเหล่านี้ทดสอบด้วย Alex จำลอง ยังไม่ได้ยืนยัน response ของร้านจริง
- ตรวจ HTTP success และไม่รับ success=false ก่อนเก็บเลขอ้างอิง เลขที่ไม่ทราบไม่ถูกเดาหรือใช้แทนกัน หากไม่พบ Order ID คงสถานะส่งแล้วแต่ผลไม่ชัดเจน และไม่ retry สร้างบิลเอง สามารถบันทึก Order ID/Order Number จากการตรวจ Alex ด้วยตัวเองได้

## ผลตอบกลับไม่ชัดเจนและการส่งซ้ำ

คำขอส่งบิลมี ID คงที่ บันทึกก่อน POST และส่งเพียงครั้งเดียว การกดซ้ำด้วย ID เดิมอ่านผลเดิม แต่ละเวอร์ชันส่งได้ครั้งเดียว (ตรวจภายใต้ล็อกของ inquiry ระหว่างส่ง กันสองหน้าต่างส่งเวอร์ชันเดียวกัน) ระบบกู้สถานะหลังรีสตาร์ตและอ่านประวัติได้แม้แชทหรือร่างเปลี่ยนไป

หาก timeout, HTTP error, หรืออ่านเลขบิลไม่ได้ จะเก็บ `SUBMIT_UNKNOWN` ไม่ส่งซ้ำ และนับว่าเวอร์ชันนั้นส่งแล้ว ล็อกของ inquiry ปลดทันทีที่ Alex ตอบ (เดิมล็อกจนแอดมินบันทึกผล) ตรวจใน Alex แล้วกด **บันทึกผลที่ตรวจจาก Alex** ได้: ถ้าพบ ให้กรอกเลขออเดอร์; ถ้าไม่พบ ต้องรออย่างน้อย 2 นาทีจากการส่งครั้งล่าสุดและตรวจ Alex ก่อนยืนยันว่าไม่ได้สร้าง (เวอร์ชันกลับเป็นยังไม่ส่ง) ถ้าจะส่งออเดอร์เดิมซ้ำ ให้โคลนเวอร์ชันแล้วส่ง โดยผลเช็คคิวจะเตือนถ้าบิลแรกสร้างใน Alex แล้ว · `active` ในบิลหมายถึงกำลังส่งเท่านั้น ตอน startup ระบบเคลียร์ `active` ของบิลที่ Alex ตอบแล้ว

ระบบไม่รับประกันการกันคิวระหว่างผลตรวจและการสร้างบิล หากมีผู้ใช้อื่นจองพร้อมกัน ผลสุดท้ายขึ้นกับ Alex

## ข้อมูลและการทดสอบ

รูปภายในเก็บ GridFS ตามอายุ `LINE_MEDIA_RETENTION_DAYS` และต้องล็อกอินเพื่อเปิด ใช้รวมกับรูปจากแชทไม่เกิน 8 MB ต่อการส่ง AI; browser ลดภาพเหลือด้านยาว 2,000 px และไม่เกินประมาณ 1.4 MB ต่อรูป ข้อมูลลูกค้าต้องมีหลักฐานข้อความลูกค้าตรงตัวและตรวจ context ใหม่ก่อนเติม

collections ใหม่: `inquiry_attachments`, `availability_checks`, `bill_reviews`, `alex_submissions`; มี index แยก shop/channel/inquiry และ unique reservation เฉพาะบิลที่กำลังส่ง (active) · `order_drafts` เก็บ `cart` ที่บันทึกพร้อมเวอร์ชัน, `copied_from`, `cancelled_at`/`cancelled_by` MCP ยังคงมีเพียงเครื่องมือค้นหาแบบอ่านข้อมูล ไม่เพิ่มเครื่องมือสร้างบิล

ทดสอบ API ด้วย MongoDB disposable: `cargo test -- --include-ignored` และ `TEST_MONGODB_URI` ที่ชี้ฐานทดสอบ การทดสอบสร้างบิลใช้ Alex จำลองเท่านั้น ส่วน production ทดสอบอ่าน login/catalog/checkq โดยไม่สร้างบิลจริง

## Build และ deploy

Windows build บน local เท่านั้น ใช้ `build-backend.bat` และ `build-frontend.bat` แล้วผู้ใช้รัน `rungit.bat "เพิ่มสรุปจากรูปและสร้างบิล Alex"` เอง เมื่อมี release พร้อมแล้ว ไม่ต้อง build โปรแกรมซ้ำบน Ubuntu

Ubuntu:

```sh
ssh Hermes
cd ~/alex-connectingpoint
bash ./loadgit.sh main
sudo bash ./docker-build.sh --full-stack
sudo bash ./docker-deploy.sh --full-stack
```

หากแก้เฉพาะ `.env` บน server ให้รันเฉพาะ deploy คำสั่งสุดท้าย ตรวจ credentials/branch และ extraction profile Hermes ตามคู่มือ Step 2/3 ก่อนใช้งานจริง
