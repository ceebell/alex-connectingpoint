# เงื่อนไข AI สำหรับออกบิลของร้าน

เจ้าของร้านเปิด **หน้าหลัก → ไอคอนตั้งค่าที่การ์ดชื่อร้าน → ตั้งค่าร้าน** เพื่อกรอกเงื่อนไข ก่อนใช้ต้องบันทึกด้วยปุ่ม **บันทึกเงื่อนไข** ตัวอย่างไม่ถูกเปิดใช้เอง พนักงานและผู้จัดการเปลี่ยนเงื่อนไขไม่ได้ รวมถึงเรียก API ตั้งค่าโดยตรง

รองรับเงื่อนไขการออกบิลภาษาทั่วไป ไม่จำเป็นต้องตรงประโยคตัวอย่าง Server ตรวจรูปแบบโค้ด/อักขระแฝง และให้ Hermes ที่ปิดเครื่องมือทั้งหมดตรวจขอบเขตก่อนบันทึก เงื่อนไขต้องเกี่ยวกับบิลของร้านนี้ ไม่รับการรันสคริปต์ การเข้าถึงร้านอื่น การเขียนฐานข้อมูลโดยตรง หรือการเปลี่ยนสิทธิ์ หากตรวจไม่ได้หรือมีส่วนใดนอกขอบเขต จะไม่บันทึกทั้งชุด และคงข้อความที่กรอกไว้

ตัวอย่างแบบแนะนำสินค้าให้แอดมินเลือกเอง:

```text
ชื่อลูกค้าทุกคนต้องมี K. นำหน้า
หากแอดมินพิมพ์สรุปยอด ค่าเช่า ค่าประกัน ให้ใช้ยอดค่าเช่า ค่าประกันที่แอดมินสรุปแล้วเป็นหลัก
ให้หาสินค้าค่าขนส่งเป็นปุ่มเตรียมใส่ตะกร้าไว้ เมื่อแอดมินกดจึงใส่ลงตะกร้า ไม่เพิ่มให้อัตโนมัติ
ใส่หมายเหตุว่า กรุณาคืนชุดก่อนเวลา 18:00 น.
```

คำแนะนำสินค้าแสดงในร่างล่าสุด ค้นแค็ตตาล็อกของร้าน/สาขาที่เลือกด้วย API เดิม และแอดมินกดเพิ่มลงตะกร้าเอง ข้อความเงื่อนไขไม่สามารถระบุ shop ID ปลายทางหรือสร้างคำสั่งค้นฐานข้อมูลเองได้ แนะนำได้ไม่เกิน 3 คำค้น และแต่ละคำต้องอยู่ในข้อความต้นฉบับจริง โหมดแนะนำค่าขนส่งจะปิดการเพิ่มค่าขนส่งอัตโนมัติ และคิดผ่านสินค้าที่แอดมินเลือกแทนค่าขนส่งในหมายเหตุ เพื่อไม่คิดซ้ำ

กฎที่ server บังคับซ้ำได้โดยตรงยังรองรับ 3 ชนิดเดิม เปลี่ยนคำนำหน้า จำนวนเงิน และรหัสสินค้าได้:

```text
ชื่อลูกค้าทุกคนต้องมี K. นำหน้า
หากค่าเช่าในออเดอร์นั้นต่ำกว่า 600 บาท จะมีค่าขนส่ง 40 บาท ให้เพิ่มค่าขนส่งจาก stock product code: 0053MNANANA
แอดมินสรุปบิลให้เอาค่าเช่า ค่าประกันตรงหน้าสรุปบิลเป็นหลัก ไม่คำนวณจากตะกร้าเอง
```

สามารถใช้กฎใดก็ได้หรือรวมกับเงื่อนไขทั่วไป เว้นช่องว่างแล้วบันทึกเพื่อล้างกฎเพิ่มเติม รองรับรูปแบบ `ชื่อลูกค้าต้องมี … นำหน้า`, `หากค่าเช่าต่ำกว่า …`, `ถ้าค่าเช่าต่ำกว่า …` และ `ใช้ค่าเช่าและค่าประกันจากสรุปบิลเป็นหลัก` ด้วย จำนวนเงินของกฎค่าขนส่งรองรับทศนิยมไม่เกิน 2 ตำแหน่ง เงื่อนไขเพิ่มเติมจะอยู่ใน guidance ให้ AI อ่านก่อนเตรียมร่าง หากขาดข้อมูลหรือทำไม่ได้อย่างปลอดภัย AI ต้องถามแอดมิน ไม่อ้างว่าได้ทำสิ่งที่ระบบยังไม่รองรับแล้ว

คำนำหน้าชื่อใช้กับชื่อลูกค้าในร่างและบิล ไม่เปลี่ยนชื่อ LINE หรือชื่อที่ตั้งให้ลูกค้าในรายชื่อ ระบบไม่เติมคำนำหน้าเดิมซ้ำ การเติมคำนำหน้าเกิดหลังตรวจหลักฐานชื่อลูกค้าจากแชท/สรุป และมีหลักฐาน `shop_billing_rule` เพิ่มในร่าง

กฎค่าขนส่งใช้ค่าเช่าสุทธิหลังส่วนลด ก่อนค่าขนส่ง ไม่รวมค่าประกัน กรณีตัวอย่าง 599.99 บาทเพิ่ม 40 บาท ส่วน 600 บาทพอดีไม่เพิ่ม การเพิ่มทำในใบสรุปออเดอร์และ payload ที่ส่ง Alex จำนวน 1 รายการ โดยค้นสินค้ารหัสตรงจากสาขาของออเดอร์ ต้องพบเพียงรายการเดียว ราคาเช่าตรงกับค่าส่งและค่าประกันเป็น 0 สินค้าต้องผ่านการตรวจ catalog และคิวเดิมก่อนส่ง ถ้าไม่ผ่านจะหยุดพร้อมแจ้งข้อผิดพลาด ไม่เดารหัส stock หรือแก้ราคาสินค้า

## ค่าเช่า/ค่าประกันตามสรุปบิล

กฎ `แอดมินสรุปบิลให้เอาค่าเช่า ค่าประกันตรงหน้าสรุปบิลเป็นหลัก ไม่คำนวณจากตะกร้าเอง` ใช้ยอดในสรุปเป็นค่าเริ่มต้น เฉพาะช่องที่ยังไม่มีส่วนลดระบุไว้ ระบบจึงคิดส่วนต่างจากราคาแค็ตตาล็อก − ยอดในสรุป เช่น ราคา 640 บาท สรุปเดิม 500 บาท และไม่มีส่วนลดระบุไว้ จะได้ส่วนลดเริ่มต้น 140 บาท แต่หากแอดมินบันทึกส่วนลด 100 บาท ต้องใช้ 100 บาท ทำให้ค่าเช่าสุทธิ 540 บาท ไม่คำนวณกลับเป็น 140 บาท รวมถึงการระบุส่วนลด 0 ต้องคง 0 เกณฑ์ค่าขนส่งใช้ยอดสุทธิหลังส่วนลดที่ใช้จริง

ถ้าสรุปบิลไม่มีค่าเช่าหรือค่าประกัน ระบบใช้ราคาแค็ตตาล็อกของรายการที่เลือกใน Alex เป็นค่าเริ่มต้นแยกแต่ละยอด แล้วแอดมินกรอกส่วนลดเองได้ ค่าส่งแยกจากฐานส่วนลดเสมอ หากยังไม่มีส่วนลดที่ระบุไว้และยอดในสรุปสูงกว่าราคาใน Alex จะหยุดให้ตรวจ เพราะ Alex ไม่มีช่องบวกเพิ่ม แต่เมื่อแอดมินระบุส่วนลดสุดท้ายแล้ว ยอดในสรุปเก่าไม่ใช้คำนวณหรือหยุดการใช้ส่วนลดนั้น ระบบยังตรวจส่วนลดไม่ให้ติดลบหรือเกินราคาสินค้า

รายการค่าขนส่งที่ใช้รหัสตามกฎจะถูกสร้างใหม่จาก catalog ในใบสรุปเพื่อไม่คิดซ้ำจากตะกร้า เมื่อมีกฎค่าส่งแบบสินค้า ระบบไม่บวกค่าจัดส่งซ้ำในช่องหมายเหตุอีก ไม่แก้ตะกร้าหรือสร้างบิลระหว่างบันทึกเงื่อนไข

## แก้ส่วนลดก่อนส่งบิล

ส่วนลดที่ระบุไว้ในร่างเป็นยอดสุดท้าย และหากแอดมินแก้อีกใน confirm modal ให้ใช้ค่าจาก modal เป็นอันดับแรก รวมถึง 0 ทั้งสองที่ การอัปเดตตะกร้าไม่แก้ส่วนลดที่แอดมินกรอก แม้จะเท่ากับค่าอัตโนมัติเดิม ไม่บวกส่วนต่างราคาหรือส่วนลดเก่าซ้อน และปิด `useDiscountPromotion` ฝั่ง Alex เมื่อใช้ส่วนลดสุดท้าย เก็บ `discounts_finalized=true` กับ group, review และผลส่ง เพื่อให้ใช้ยอดเดียวกันตั้งแต่ร่าง ผ่าน modal จนถึง payload ที่ส่งจริง

ไม่มีช่องค่าส่งแยกในร่างหรือ modal ค่าส่งคิดผ่านสินค้าที่แอดมินเลือกในตะกร้าและรวมอยู่ในยอดเช่าของ Alex เท่านั้น ยอด shipping_fee_satang ที่อาจค้างจากร่างหรือ client รุ่นเดิมไม่ถูกนำมาบวกหรือเขียนต่อท้ายหมายเหตุ ระบบเริ่ม review ใหม่เมื่อ pricing policy เปลี่ยนเพื่อไม่ใช้ payload เก่า

สินค้าในตะกร้าที่เป็นค่าส่ง (`is_shipping=true`) ยังส่งเป็น `orderItems` ในออเดอร์เดียวกัน และรวมราคาเต็มในยอดค่าเช่าของ Alex แต่ไม่รวมในฐานคำนวณส่วนลดทั้งร่าง/ใบสรุป/ตรวจร่างฝั่ง server แอดมินเปลี่ยนป้าย **รายการค่าส่ง · ไม่คิดส่วนลด** ในตะกร้าได้ รหัสสินค้าค่าส่งที่ตั้งในกฎร้านและชื่อที่ขึ้นต้นว่าค่าส่ง/ค่าขนส่งจะถูกระบุให้เบื้องต้น ระบบไม่อนุมานว่าเป็นค่าส่งจากราคา 40 บาทเพียงอย่างเดียว ป้ายถูกเก็บไปกับ snapshot ตะกร้าของร่าง เมื่อมีสินค้าค่าส่งจะไม่บวกค่าส่งจากร่างซ้ำ

ในใบสรุปก่อนส่งเข้า Alex แอดมินแก้ส่วนลดค่าเช่าและส่วนลดค่าประกันได้เป็นบาท ทศนิยมไม่เกิน 2 ตำแหน่ง ระบบแสดงยอดสุทธิใหม่ และตรวจค่าขนส่งตามเงื่อนไขร้านอีกครั้ง หากยอดค่าเช่าข้ามเกณฑ์จะเพิ่มหรือเอาสินค้าค่าขนส่งออกให้ตรงกัน ไม่มีการสร้างบิลระหว่างแก้ยอด

ยอดจากร่างหรือกฎสรุปบิลเป็นค่าเริ่มต้น การแก้ส่วนลดในใบสรุปโดยตรงใช้แทนค่าเริ่มต้นสำหรับการส่งครั้งนั้น กด **ใช้ส่วนลดจากร่าง** เพื่อกลับไปใช้ค่าเดิม การแก้ในใบสรุปไม่บันทึกกลับเป็นร่าง AI ใหม่ ส่วนลดต้องไม่ติดลบหรือเกินราคาใน Alex และลดเฉพาะสินค้าเช่า ไม่ลดสินค้าค่าขนส่งที่ระบบเพิ่มตามกฎร้าน

`POST /api/inquiries/{id}/checkout/amounts` ตรวจและแสดงยอดโดยไม่เขียนบิล ส่ง `source_hash`, `group_key` และส่วนลดหน่วยสตางค์ คืนกลุ่มสินค้าและ `amounts_hash` ให้หน้าเว็บส่งพร้อมข้อมูลตรวจร่าง หากยอดหรือรายการเปลี่ยนระหว่างแสดงกับส่ง ระบบหยุดให้ตรวจใหม่ ข้อมูลที่ส่งจริงเก็บส่วนลดที่แก้และผู้ส่ง/เวลาส่งใน `alex_submissions` โดยไม่เพิ่มขั้นตอนยืนยันซ้ำ

## การจำกัดขอบเขต

ช่อง **หมายเหตุ / อุปกรณ์** ในใบสรุปก่อนส่งเริ่มว่าง ไม่คัดลอกหมายเหตุจากร่าง AI อัตโนมัติ เพื่อไม่ให้ข้อสงสัยวันคืน รายชื่อขนส่ง คำแนะนำขั้นตอนทำงาน หรือเวลาในแชทติดไปกับ remark ของ Alex แอดมินกรอกหมายเหตุที่ต้องการส่งเองได้ หมายเหตุในร่างเดิมยังเก็บไว้ให้อ่าน ไม่บวกยอดค่าส่งจากช่องเดิมหรือเขียนค่าส่งแยกต่อท้ายหมายเหตุ การเปลี่ยนนี้ไม่แก้ตะกร้าหรือประวัติออเดอร์ที่ส่งแล้ว

- Server เก็บเงื่อนไขเป็นข้อมูล ไม่เรียก eval, shell, JavaScript, URL หรือ database query จากข้อความ การตรวจคำสั่งเป็นชั้นเสริม สิทธิ์และขอบเขตร้านถูกบังคับด้วย API/DB ฝั่ง server ไม่อาศัยคำตอบของโมเดลเป็นตัวให้สิทธิ์
- ข้อความภาษาทั่วไปผ่าน semantic scope check ด้วย system prompt คงที่ ตรวจ toolsets ว่าปิดจริง ใช้ tools=[]/tool_choice=none และ namespace ใหม่ที่ผูกกับร้าน/channel ไม่ให้ใช้บริบทของร้านอื่น ผลตรวจรับเฉพาะ schema ที่กำหนดก่อนบันทึก policy_schema=2 และนำ guidance ไปให้ AI อ่านเป็นข้อมูลนโยบายที่มีอำนาจจำกัด
- ร่างอ้าง guidance เป็นหลักฐานได้เฉพาะหมายเหตุและข้อเสนอส่วนลด/ค่าขนส่ง ไม่ใช้แต่งข้อมูลลูกค้า รหัสสินค้า วันที่ หรือราคาฐาน ต้องมีหลักฐานจริงเหมือนเดิม การเสนอสินค้าไม่เขียนตะกร้าจนแอดมินกด API เพิ่มรายการตามปกติ
- ชื่อ ค่าขนส่ง และยอดค่าเช่า/ค่าประกันถูกตรวจซ้ำด้วยโค้ด server ไม่อาศัยว่า AI จะทำตามข้อความเสมอ ยอดที่มีในสรุปบิลมีลำดับก่อน หากไม่ระบุจึงใช้แค็ตตาล็อก Alex ที่ตรวจสอบได้และให้แอดมินใส่ส่วนลด ถ้ายอดสูงกว่าราคาใน Alex หรือแค็ตตาล็อกไม่ครบจะหยุดก่อนสร้างบิล การสร้างบิลยังผ่านสิทธิ์ผู้ส่ง คิว ต้นฉบับล่าสุด และระบบกันส่งซ้ำเดิม
- บันทึกแยกตาม `shop_id` และ `channel_id` มีเลขเวอร์ชัน ผู้แก้ และวันเวลา เก็บประวัติล่าสุด 100 ครั้ง ใช้ expected version กันการเขียนทับจากสองหน้าต่าง เมื่อชนกันจะคงข้อความที่กำลังแก้ไว้ให้ผู้ใช้เลือกโหลดค่าล่าสุด
- งาน AI ผูกกับเวอร์ชันกฎตอนเริ่ม หากกฎเปลี่ยนระหว่างงาน ผลเดิมจะเป็น stale และต้องเตรียมใหม่ ใบตรวจบิลใช้ source hash ที่รวมกฎและสินค้า จึงส่งใบตรวจเก่าต่อไม่ได้หลังเปลี่ยนกฎ บันทึกเวอร์ชัน/กฎที่ใช้กับใบตรวจและบิลเพื่ออ้างอิงย้อนหลัง

API ตั้งค่า: `GET /api/admin/shop-settings` และ `POST /api/admin/shop-settings` โดย POST รับเฉพาะ `instruction_text` กับ `expected_version` ใช้ session/CSRF และสิทธิ์เจ้าของร้าน เก็บใน collection `shop_settings` ไม่ต้องเพิ่ม env หรือส่ง token ไป frontend

หลังแก้เงื่อนไข ให้เตรียม AI ใหม่เพื่อให้ร่างอ่านกฎใหม่ และโหลดร่างล่าสุดใหม่เพื่อดูคำแนะนำสินค้า ใบสรุปก่อนส่งจะใช้กฎล่าสุดของร้านเสมอ กฎเดิมที่แปลงเป็น typed rule ได้ยังบันทึกและอ่านได้โดยไม่ต้องเรียก AI ตรวจภาษา ส่วนเงื่อนไขทั่วไปต้องมี Hermes พร้อมใช้งานและปิดเครื่องมือทั้งหมด
